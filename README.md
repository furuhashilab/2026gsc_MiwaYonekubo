# 日本映画のロケ地巡礼マップの開発
本研究は卒論時まで継続的に行う研究としてWebサイト、もしくはアプリケーション作成を目的とする。

## 概要（Abstract）
対象テーマ：日本映画を軸とした国内コンテンツツーリズムおよびアクセシビリティ向上に関する研究
方針：本研究は現段階においてアイデアの構想・設計段階にあるため、今後は「プロトタイプの早期実装」「ユーザビリティの検証」「データ検証」という３つのフェーズを段階的に踏むことで、客観的な成果と結論を導き出す。
主要な動き：映画のロケ地データを集約し、誰もが直感的に利用できる「聖地巡礼マップWebアプリケーション」の試作と実装
アプローチ：アプリケーション開発と観光行動の分析は、システム設計（エンジニアリング的アプローチ）とフィールドワーク（社会科学的アプローチ）の両面を必要とするため、明確な目標設定をしながら進める。

## 導入（Introduction）
本研究では、コンテンツツーリズムをテーマとし、日本映画で使用された国内のロケ地を巡礼できるWebアプリケーションの開発に取り組む。

研究背景：アニメやドラマの聖地巡礼に関する先行研究や観光振興事例は豊富である一方、「日本映画」のロケ地に特化した観光動向や情報アクセスの仕組みに関する研究は少ない。
また、日本映画作品は地域の日常的な風景を情緒的に切り取るため、公開後の観光誘致において高いポテンシャルを秘めている。

## 今後の研究目標（Milestones）
 成果を生み出すために、以下の3つの具体的な目標を設定する。
1.「探す手間」をなくすデータの一元化：ネット上にバラバラに点在している日本映画のロケ地情報やアクセス方法を体系的に収集し、アプリケーションから一目でわかる状態のデータベースを構築する。

2. 誰でもすぐに使えるアクセシビリティの追求：特別な操作や複雑な操作を一切不要とし、現在地からロケ地までのルート案内が起動するWebアプリケーションを設計・実装すること。

3. 観光業に対する明確な効果の検証：実際に試作したアプリを用いた検証実験を通じて、「観光客のフットワークが軽くなったか」「聖地巡礼によって未上陸地への旅が可能になったか」「どれくらい移動しやすくなったか」など、アンケートのデータをもとに証明をする。

## 具体的なスケジュール案（今後のロードマップ）時期実施内容（タスク）主要なマイルストーン・成果物

全体スケジュール案（9〜2月・翌年以降）

第1フェーズ：基盤固めと設計（9月上旬~10月中旬頃）

9月上旬〜中旬：対象作品の選定とデータ収集 _マップに掲載する日本映画を3~5作品程度に絞り込み、ロケ地の住所やアクセス情報をリスト化する。_

第2フェーズ（11月頃）システム実装（コーディング）・フロントエンドおよび地図API（Leaflet等）の実装・ロケ地データベースとの紐付け作業・プロトタイプ版（Ver.1.0）のリリース・動くプロトタイプ（Webアプリ）の完成

第3フェーズ（8月〜9月頃）検証実験（ユーザビリティテスト）・被験者を募り、アプリを用いた模擬的な聖地巡礼テストを実施・アンケート調査（操作性、回遊意欲、満足度）の回収・評価データの収集完了・データ集計の実施

第4フェーズ（10月〜11月頃）分析・考察・追加改修・収集したデータの統計処理・分析・結果から見えた課題（アクセシビリティや課題点）の深掘り・考察部分の論理構築・アプリのブラッシュアップ

第5フェーズ（12月〜1月頃）ゼミ論執筆・ファイナライズ・全体の文章化（概要からまとめまで）・図表の整備、プレ発表に向けたスライド作成・ゼミ論提出・最終論文の完成

成果を生み出すための「評価指標（KPI）」定量評価:情報探索にかかった時間（既存の検索エンジン・ブログ等との比較実験）アプリの読み込み速度、操作ステップ数定性評価:「直感的に操作できたか」「実際にその場所に行きたくなったか」に関する主観評価アンケート（リカート尺度による5段階評価および自由記述）


## 予想されるリスクと事前の対策（コンティンジェンシー・プラン）

リスク1: 開発の遅延対策: 最初から完璧な機能を盛り込まず、まずは地図とピン立て機能のみの最小限（MVP）から公開し、段階的にアップデートするアジャイル開発的な手法をとる。

リスク2: 被験者の確保難対策: ゼミのメンバーや学内を対象にした手軽なテスト環境を早期に構築し、テストのハードルを下げる。
